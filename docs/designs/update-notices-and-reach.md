## Problem Statement

The user asked for four things on top of the original design:

1. The README must show and explain everything Astrolabe displays: what each piece of
   information on screen actually means. Its prose goes through the humanizer skill.
2. The mod must work on Linux, macOS and Windows, and in the Claude Code Desktop app if
   possible.
3. The mod must be installable straight from Claude's own marketplace.
4. The mod should tell the user when gstack skills, the Spec Kit CLI (`specify`) or
   Astrolabe itself have an update, with a notice the user can click to install it. The
   check runs once per new day or new session.

## Constraints

Checked during this session:

- **Official marketplace.** `anthropics/claude-plugins-official` takes third-party plugins
  under `external_plugins/`, accepted through the plugin directory submission form
  (`https://clau.de/plugin-directory-submission`). Plugins "must meet quality and security
  standards for approval." Only the user can submit the form.
- **Update checks exist already.** gstack ships `~/.claude/skills/gstack/bin/gstack-update-check`.
  Spec Kit 1.1.1 has `specify self check` (read-only) and `specify self upgrade`. Project
  skills are refreshed with `specify init --here --ai claude --force`, which a user should
  run deliberately because it rewrites `.claude/skills/speckit-*`.
- **The status line takes no clicks.** `$.ui.status` is plain text. Buttons live in the band
  (`AbovePrompt`, spec 002) and the pane (spec 004).
- **Network.** Knowing Astrolabe's latest release needs a call to the GitHub releases API.
  Constitution Principle XII forbids network calls unless a spec adds one and the README
  documents it.
- **Processes.** `$.process.run` is allowed in event hooks and button handlers, never on
  the draw path (Principle XII).
- **Surfaces.** Mods draw in the terminal (2.1.287 or later) on all three operating systems
  and in the Desktop app's Code tab (2.1.286 or later). VS Code, `claude -p` and cloud
  sessions run the hooks but draw nothing.

## Premises

Confirmed by the user (D1, option A):

1. The README explains every reading Astrolabe shows, and its prose is humanized. This lands
   in spec 001 (task T044) and grows with each later spec.
2. Linux, macOS, Windows and the Desktop app's Code tab are supported. CI runs the tests on
   all three operating systems from spec 001. VS Code and `-p` draw nothing, and the README
   says so.
3. The official marketplace needs the submission form, which the user sends. The repository
   gets ready for it in 001 (complete manifests, license, README, tagged v0.1.0), and the
   form is filled in together in the browser after the release.
4. Clickable update notices become a new spec, `007-update-notices`, built on the band (002)
   and the pane (004). They are not part of v0.1.0.

## Approaches Considered

### Approach A: the click fills the prompt
The button puts the command (`/gstack-upgrade`, `specify self upgrade`) in the prompt with
`$.prompt.fill`; the user presses Enter. Simple and safe, but two steps. Not chosen.

### Approach B: the click runs the upgrade and shows the result (chosen)
The button runs the upgrade with `$.process.run`, the pane shows its output, and a toast
reports success or failure with the command to retry by hand.

### Approach C: toast only
A toast says an update exists, with no click. Does not meet the request. Not chosen.

## Recommended Approach

**B**, in spec `007-update-notices`, after 002 (band) and 004 (pane).

- **When.** At `session.start`, if `$.store` holds no check for today's local date, run the
  checks and store the date and results. Later sessions that day reuse the stored results.
- **What is checked.**
  - gstack: `gstack-update-check` through `$.process.run`, when the binary exists.
  - Spec Kit CLI: `specify self check`, when `specify` is on the path.
  - Spec Kit project skills: compare `.specify/integrations/speckit.manifest.json`'s
    `version` with the installed `specify --version`; a newer CLI means the project skills
    can be refreshed.
  - Astrolabe: one `GET https://api.github.com/repos/jonyfs/astrolabe/releases/latest`,
    compared with `plugin.json`'s `version`. Documented in the README as the mod's only
    network call, with a `userConfig` switch `checkUpdates` (default on) to turn it off.
- **What is shown.** A compact `updates: gstack · specify · astrolabe` segment in the band
  with one Button per item; the pane's Session tab lists versions (installed and latest).
- **What a click does.**
  - gstack: runs gstack's upgrade script.
  - Spec Kit CLI: `specify self upgrade`.
  - Spec Kit project skills: asks first (it rewrites `.claude/skills/speckit-*`), then runs
    `specify init --here --ai claude --force`.
  - Astrolabe: `claude plugin update astrolabe@<marketplace>`, then tells the user to run
    `/reload-plugins`.
  Each run streams into the pane, has a timeout, and ends with a toast: `updated gstack to
  x.y.z` or `specify upgrade failed: <first line>; run specify self upgrade`.
- **Tests.** Fixtures answer `process.run`, `net.fetch` and `store.*` from memory: no update,
  one update, a check that fails, a missing binary, a second session on the same day.

## Success Criteria

- The README has a section for every reading on screen saying what it shows, where the value
  comes from and an example, written plainly.
- `claude plugin test .` passes in CI on Ubuntu, macOS and Windows.
- Astrolabe is listed in the official directory and installs with
  `/plugin install astrolabe@claude-plugins-official`.
- With an update available, one click installs it, and the pane shows the result.
